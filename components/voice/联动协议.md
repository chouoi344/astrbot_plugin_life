# 语音已发送正文协议 v1

自然语音从 0.1.4 起，在原始 AstrBot 消息事件中提供 `life_voice_delivery_v1`。它供其他插件读取已发送台词，不依赖日程插件，不调用日程对象，也不等待日程判断。

从 0.1.9 起，OneBot QQ、QQ 官方私聊及个人微信的普通工具调用也按明确回执登记。个人微信 `weixin_oc` 的普通工具、忙碌补答和主动入口直接发送清理后的文字，跳过语音合成。主动和忙碌的 `event.send` 契约保持一致，由调用方选择目标和传递最终准入检查。

## 数据与有效范围

```python
deliveries = event.get_extra("life_voice_delivery_v1", [])
```

值为按成功发送顺序追加的列表，每项包含三个字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `str` | 对 `text` 的 UTF-8 字节计算 SHA256，使用小写十六进制字符串 |
| `text` | `str` | 实际交付的清理后正文，已经去掉声音标签 |
| `medium` | `str` | `voice` 表示语音发送成功，`text` 表示成功回退成文字 |

每份列表只属于当前消息事件；不落盘，不包含密钥、音频内容、音频路径或日程资料。不同事件说出相同正文时，`id` 相同，但它们是两次独立交付，不能跨事件按此 ID 去重。

消费者只读列表，不删除、清空或修改原始条目。消费者自己的处理状态另存在当前事件中；重复收到完成通知时，只消费尚未处理的条目。

## 什么时候记录

- 只有发送确认后才追加条目。OneBot QQ 使用服务端消息编号。QQ 官方还要求成功 HTTP 状态、无业务错误，报告去重或回执无法解读时按未确认处理。个人微信以适配器接受为确认，网页聊天以当前请求队列接受消息为确认。
- 语音发送成功记录 `voice`。语音生成失败后改发文字、个人微信直接发文字，均以实际发送成功的文字登记为 `text`。QQ 发送结果不明时停止发送，不追加条目。
- 合成完成但尚未发送、发送抛错且文字回退也失败、发送等待被取消，都不记录这次交付。
- 同一事件相同清理后正文只发送并登记一次；后续不同正文追加独立条目。后续失败不会删除此前已经成功的条目。
- 缺配置、插件关闭、群聊、无可朗读正文等未交付情况，不产生新条目。

条目由 `_send_speech()` 写入，工具 `tts_speak(text)` 成功交付时会先登记、清空当前结果，再以 `None` 结束本轮。原有 AstrBot 4.26–4.28 历史兼容保持不变。

## 日程端如何接收

可在 AstrBot 的 `on_llm_tool_respond` 事件中读取。真实 4.26.0、4.27.5、4.29.0 已验证：工具结束通知发生时，条目已可读取，当前消息结果已清空。

`tool_args.text` 只表示请求发送的台词，不证明交付；`tool_result` 也不能代替此记录。日程端应验证记录格式，保留自己的主人、角色 token、启用状态、会话限制和聊天改日程开关，再按原规则将实际正文入队。

同一事件可能有多次工具完成通知，每次都能读到累计列表。接收方按当前事件内的 `id` 去重，并与自己的普通文字采集入口合并去重，避免同一句回退文字被处理两遍。语音只提供事实，是否包含约定由日程原有逻辑判断。

语音发送完成不等待日程消费。消费者异常应由消费者处理并明确记录，不能因此重新发送、重新合成或影响已交付内容。没有消费者、消费者关闭或被当前会话过滤时，语音仍可独立使用。

`/life_voice_test` 也复用发送函数，但它不是模型工具完成事件。本次聊天联动的接收路径是 `tts_speak`，不能假设执行试听命令就会触发日程判断。

## 主动消息入口

自然语音 0.1.8 提供插件间调用方法。主动消息插件传入属于目标私聊的发送事件、完整台词和异步检查函数。

```python
receipt = await voice.send_proactive_voice(event, text, before_send=still_allowed)
```

`still_allowed` 是零参数异步函数，返回布尔值。自然语音在实际合成前检查一次，在实际发送前再检查一次。后一检查同时适用于合成失败后的文字回退。

| `status` | 含义 |
| --- | --- |
| `sent` | 平台发送接口确认成功，`deliveries` 记录这一条 |
| `failed` | 无法准备本次发送，或平台接口明确返回 `False` |
| `cancelled` | 检查返回 `False`，或该事件已确认发送相同台词 |
| `unknown` | 已尝试发送，平台抛错、超时或没有给出明确确认 |

`deliveries` 只包含本次调用确认的交付，每项为 `{"medium": "voice" 或 "text", "text": "清理后的实际台词"}`。回执可包含适合显示的 `error`。带标签台词用于合成，文字回退和回执使用去标签正文。

一次调用发送一条完整语音或一条回退文字。多条台词由主动插件分次调用并累积成功回执。后续取消或失败时，此前确认的正文仍保留。同一事件内，已确认的台词重复调用返回 `cancelled` 和空列表，结果不明的台词重复调用仍返回 `unknown` 和空列表。调用方遇到 `unknown` 应停止补发该条，即使下一次使用新的事件对象。

发送事件的 `send` 方法须只尝试一次交付，确认送达时明确返回 `True`，明确未发时返回 `False`。超时和结果不明通过异常传递。原生 SDK 的 `None` 返回值无法区分已发与空实现，主动入口将它计为 `unknown`。调用方应提供能确认结果的适配器，交付后的历史由主动插件统一记录。

主动发送适配器每次开始发送时清空 `event.delivery_status`。如果最后一道检查拦截且确定未调用平台，设置 `cancelled` 或旧版的 `stopped`，自然语音在 `False` 或异常时返回 `cancelled`。如果平台明确拒绝或消息确定未发出，设置 `failed`，自然语音在 `False` 或异常时返回 `failed`。已尝试发送但没有确认时设为 `unknown` 并抛出异常，不沿用上一次发送的状态。

单次交付运行于独立任务。语音插件关闭时停止该次交付，调用方可以继续处理回执。外部任务取消会继续向上抛出 `CancelledError`。实际发送开始后的取消会在同一事件中留下未确认标记，供后续调用防止重发。合成或检查期间取消且尚未调用平台时，后续可由调用方重新决定。

普通原生聊天在音频转换、上传或会话准备结束后复查关闭状态，再提交消息。关闭拦截按取消处理，不触发文字回退。网页聊天只向仍活跃且未满的请求队列立即提交。联动事件继续由发送适配器执行最后一道准入检查。

成功交付也会追加当前事件的 `life_voice_delivery_v1`。主动消息插件依据本次回执统一记录聊天历史和日程联动。该入口是普通插件方法，供主动调度调用。

## 忙碌补答入口

忙碌插件走原聊天工具 `tts_speak`，并通过 `event.set_extra("life_busy_media_guard_v1", guard)` 提供同样的无参数异步检查。带此标记的 `tts_speak` 复用主动入口的两次检查和发送确认规则，仍在成功后提供 `life_voice_delivery_v1`。`event.send` 的 `True` 表示平台已确认，`False` 表示明确未发送，发送异常或无明确回执按 `unknown` 处理。

作废、发送失败或结果不明时，语音工具结束当前补答，避免模型再补一条正文。合成失败且补答仍有效时，允许回退为一条清理后的文字。忙碌插件负责在实际 OneBot 发送动作处检查队列归属，并管理 `life_delivery_v1`。普通聊天仍走原 `tts_speak` 发送路径。
