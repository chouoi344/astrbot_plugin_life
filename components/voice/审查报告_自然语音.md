# 自然语音 v0.1.0 候选版审查

日期：2026-11-06。范围：独立语音工具、第三种声音标签效果、可选语音识别、旧插件隔离。日程读取与主动推送明确不在本轮范围。

## 依据与实现

- 基础包：用户提供的 MiniMax v0.1.12，SHA256 `2b8ac7e5f9fac27f4279922a66549f4ce7e3e28e1707b7249e8a7790e508eeae`。原包与解压参考源码保留。
- 复用原语音工具直接发送、清空当前结果后结束工具循环、合成/展示双文本、音频缓存与原子保存机制；移除 MiniMax 专用接口、音色映射、旧 EMO 情绪路由及机械分段。
- 中文标签、动作映射与固定请求体来源于用户实际试听选定的“第三种”，请求体没有 `instructions`。
- 实际 AstrBot 4.29.0 源码已核对工具调用的停止语义、历史保存、STT 预处理顺序、工具超时与中间文字缓冲。最低版本明确为 4.29.0，不增加写聊天数据库的兼容补丁。

## 对抗检查发现及修正

| 问题 | 处理与验证 |
| --- | --- |
| 默认空密钥导致首次安装失败 | 仅完整配置时创建语音客户端；空设置加载、状态指令及独立识别均已测试 |
| 普通强调与括注中的关键内容被删除 | 保留普通括注和强调正文，仅转换已知声音动作、清理明确旁白；取消订单和就医证件例子已回归 |
| 服务等待时间超过核心工具超时，正文来不及回退 | 取当前会话工具超时的 80%，上限 90 秒；主动超时后直接发送完整干净正文 |
| 一个等待者取消会连带取消其他会话的相同请求 | 共享已开始的请求，等待者取消隔离；关闭客户端时统一取消并等待内部任务 |
| 全部等待者离开后，排队任务仍开始新的付费生成 | 跟踪等待人数与请求是否开始；无人等待的排队任务取消；明确未受理的忙碌响应后也不继续无人等待的重试 |
| 识别任务在卸载后仍继续运行 | 识别与语音生成都登记活动任务；卸载取消等待，关闭状态不再接收新识别 |
| 核心文字缓冲在语音后追加正文 | 已有交付的本条事件清理后续普通文字，保留非文字组件；新用户消息不受影响 |
| 与旧 MiniMax 工具及其它会话相互影响 | 独有插件、命令、工具、配置及数据目录；按请求复制工具集合，仅移除本插件的工具 |

## 验证结果

- `pytest -q`：71 项测试通过，63 个子场景通过；全部为离线模拟。
- `ruff check` 与 `ruff format --check` 通过。
- 9 个 Python 文件按 Python 3.10 语法解析通过；实际本地测试使用 Python 3.12。
- 在本机 AstrBot 4.29.0 的独立进程里完成真实导入、工具参数登记、空配置初始化、真实 Record/Plain 消息对象发送、同事件去重、失败正文回退与群聊工具隔离。语音服务和消息发送出口使用替身；没有安装进正在运行的机器人。
- MP3 测试样本由本机 ffmpeg 离线生成，MPEG2.5 / 11025 Hz / ID3v2.4 样本可实际解码。
- 安装包使用明确文件列表，只含运行源码、设置、元数据、依赖和说明；逐文件与源码核对，不包含真实密钥、音频、配置、缓存、虚拟环境或开发测试。

## 尚未验证与已知边界

- 没有调用真实 BreezeBlue 或语音识别服务，没有验证实际发音、积分消耗或 QQ/NapCat 音频送达；这些须由用户安装试听验收。
- 模型在语音工具调用前已经发出的文字或流式片段无法追回。工具说明要求不发预告；工具之后的续写和事件缓冲有处理，没有用无效钩子冒充前置文字拦截。
- 旧 MiniMax 和新语音工具同时提供给模型时，选择哪一个仍由模型决定。测试新声音应只启用新工具；本插件不修改旧插件开关。
- 没有推送代码、创建远程仓库、公开发布或打版本标签。
