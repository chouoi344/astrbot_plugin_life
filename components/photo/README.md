# 自然照片

独立的 AstrBot 私聊生图插件。支持用户要求的生活照、普通文生图、消息图片修改、最多四张成组照片，以及角色与指定人物合影。

生活照可读取已启用的“拟人化生活日程 Plus”的当前活动、地点、穿搭、天气和心情。没有安装、没有启用或当前日程未就绪时，只按用户明确要求拍摄，不编造当前生活；不会为照片生成或修改日程。

## 配置

登录 AstrBot 管理后台后，打开「扩展功能 → 自然照片」管理参考图。上传、替换和删除都会立即保存。每张图片支持 20 MB 以内的 JPG、PNG 或 WebP。

- **人物面部三视图**建议按正脸、左45度、右45度上传，第一张是主要面部参考。升级时原有图片和顺序直接沿用。
- **身材视图**可选最多三张全身图，供支持多参考图的模型参考角色的肩腰腿比例与身体轮廓。只在单人全身的新拍或续拍时使用。面部以三视图为准，穿搭按日程或你的要求。留空即可沿用原拍摄流程。

原生设置保留文生图、改图、自拍参考开关，以及生图服务地址、API Key 和模型名称。升级时会把旧参考图一次性登记进面板的参考图清单。删除只将选中的图片移出使用中的参考图库。删除或替换后，原文件仍保留。打开面板、保存设置和重载均不会自行请求生图。

## 使用

直接聊天，例如“想看看你”“今天穿什么，拍给我看看”。现有聊天模型结合人设、聊天和日程理解拍摄意图，并在同一次工具调用里安排每张的拍法、距离、动作和表情，不新增规划模型。

“再来两张”“换个角度”会承接本会话、本角色最近成功的照片；“把刚才那张再发一下”“这组第二张再发我一下”复用对应原文件，不请求生图服务。四张组照后单独续拍，还可以说“把刚才那组第二张原图发我”。修改刚才的成功照片时可以同时提供本轮新素材，例如给原图换成刚上传的背景。

合影人物素材可以是真人或虚构人物。优先用本条发的图片，其次用本条引用的图片。本条既没有图片也没有引用时，可明确指定紧邻上一条上传的唯一一张图，限同一会话、角色和发送人。待匹配的素材在插件内存最多保留两分钟，成功合影续拍沿用原来的两个人，明确更换合影对象时使用新素材。重载后仍可重发已成功发送的原图，续拍合影缺少原人物素材时需重新发送或引用。

支持后台拍摄的非流式私聊可先让角色回应，再发送成片并接一句配话。其他私聊在同一轮发送成片。主动消息由联动插件调用拍照入口。

成组照片保持同一份生活背景、人物、衣服与画风，每张可改变镜头距离、角度、可见动作与表情。新拍的单人人像组照有角色参考及明确的日程地点和穿搭时，明显改变取景或机位的后续照片沿用角色参考和场景文字，减少首图构图对后续的影响。需要首图维持连续性时，由支持多参考图的模型沿用首图；用户明确要求同一构图时按要求拍摄。近景采用合理手机自拍距离，全身可用固定手机定时或场景中的镜面。用户只指定“全身”或“微笑”等一项时，其他维度仍可变化，否定要求保持否定。

自拍习惯与神态由当前人设性格、互动和心情决定，不设固定男女动作库，不根据名字或参考图猜性别。用参考图约束人物身份和原画风，表情按需求变化。仅支持单张参考图时，新拍使用第一张角色图，续拍使用选中的成片。合影与多原图改图需要支持多图参考的模型。

食物照默认像在餐桌前用手机后置随手记录：普通吃饭距离、轻俯角和现场光线，保留适量已有容器与桌面，不默认广告摆盘和精修，也不强添餐具、手、污渍或模糊。用户明确要求的食物、容器、特写和摄影风格优先；食物与场景不套用人物画风限制。

新拍、普通生图与改图统一默认 3:4；用户明确要求横图、正方形或其他支持的比例时按要求出图。尺寸优先使用约定的精确 4K 像素；服务明确拒绝尺寸时，同一比例降到 2K 重试一次。超时、断线或服务端受理情况不明确时不自动重试，避免重复费用；发送结果不明确时也不重新发送。

发送前若切换了全局角色、停用了插件或会话，将停止旧任务。同一张人设正文修改不自动取消本次已确定的快照。后台任务在重载后标记中断，不自动继续收费。

可用 /life_photo_status 查看设置状态和最近问题。生成照片最多缓存五十张，按当前会话与角色保存最近两批成功成片的分组、文件编号、拍摄摘要和生活快照；不保存完整聊天、密钥或原始合影素材。独立任务可并行生成，同会话的每组发送与成功索引更新保持完整，组内按顺序生成。

0.1.18 候选补充 AstrBot 版本兼容检查。旧版 WebChat 主动发送会核对接收队列仍有效，照片完成后的配话保留为文字回复。

多张组照可能超过 AstrBot 原生默认工具等待时间。单张生图的 180 秒总预算包含尺寸回退与明确限流重试，最多四张；本机实测由用户确认将 AstrBot 工具等待上限设为 1800 秒。插件不会修改全局等待设置。

## 主动照片调用

主动插件在选定私聊和当前日程后，可调用 `await send_proactive_photo(event, user_prompt, photo_type="selfie", shot_plan=None, before_send=check)`。每次拍一张生活照，默认比例为 3:4。拍摄方案可用一个包含 `capture`、`framing`、`angle`、`action`、`expression` 的字典，或只含该字典的列表。异步 `check()` 在生成前及实际发送前检查是否仍允许发送。调用方负责主动消息的会话事务与历史。

QQ OneBot 需要已绑定机器人的私聊事件，`event.bot.send_private_msg` 提供 OneBot 协议回执，数字发送对象与私聊会话一致，`event.message_obj.self_id` 是目标机器人的 QQ 号。WebChat 需要事件的消息编号已绑定该会话的活动订阅队列，普通聊天请求队列用于同轮回复。成功回执包含 `status="sent"` 以及一条 `deliveries`，条目有 `medium="photo"`、相册编号 `photo_id` 和拍摄意图摘要 `text`。失败、取消与送达未确认分别返回 `failed`、`cancelled`、`unknown` 和空的 `deliveries`。

带有忙碌补答媒体守卫的照片工具沿用原私聊事件。生成和每次实际发送前检查补答是否仍有效，发送与历史归属由忙碌插件确认。

## 版本兼容

最低要求 AstrBot 4.26.0。主动 WebChat 发图需要同会话的活动订阅。图片准备时如果连接已断开，按送达未确认处理。安装新版本后，原有参考图库和照片记录继续使用。

## 平台

- QQ OneBot 和 WebChat 沿用现有私聊照片发送。WebChat 主动发图要求同会话的活动订阅。
- 官方 QQ（长连接及 Webhook）只支持 C2C 私聊。普通回复使用同一条入站消息的编号，由平台判断该编号是否仍有效。上传图片后仅提交一次发送。平台返回消息编号后才确认发送成功。
- 个人微信 iLink 需要账号已登录，并且已有该私聊的上下文凭据。原生图片上传后才提交发送，以 SDK 对平台业务响应的判断为准。
- 官方 QQ 与个人微信的主动或忙碌补答由调用方提供 `life_photo_ack_v1=True` 的私聊事件。该事件的 `send()` 只在平台确认时返回 `True`，明确拒绝或撤回时返回 `False`，未确认时按送达未知处理。

官方 QQ 和个人微信只做了本机 SDK 断网验证。两种渠道的真实收件仍待配置账号后验收。
