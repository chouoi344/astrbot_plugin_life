# 自然私聊与媒体联动

主动联系与忙碌补回由 `astrbot_plugin_life_busy` 内部统一调度。发送前仍核对相同的私聊、机器人账号、入站版本和日程，并先处理已经到达的用户消息。媒体和记忆的事件标记沿用下列协议。

## 自然语音和自然照片

在补回事件上，`guard = event.get_extra("life_busy_media_guard_v1")`。它是一个无参数的异步函数，`await guard()` 返回当前媒体工作是否还能继续。检查应放在调用付费生成接口前，以及发送前。

- 有此标记的照片工具沿用同一个原事件，走已有的 `_run_job(job, event=event)` 同轮分支。只在该标记出现时关掉 QQ 后台候场与独立配文回合。把 guard 传给 `_check_job` 或现有逐张生成、发送的检查点，作废时用已有的停止路径。照片插件类以 `life_busy_media_guard_v1 = True` 声明支持。
- 有此标记的语音工具在合成前和实际发送前检查。作废时返回停止结果，不进入文字回退。实际发送走当前 `event.send`，由忙碌插件在最后的平台请求前确认队列归属。个人微信的 `life_busy_voice_supported_v1` 为假，本轮移除语音生成并让模型用文字说出台词。
- QQ 官方和个人微信补回事件声明 `life_photo_ack_v1=True`。`event.send` 的 True 表示平台确认接受，False 表示明确拒绝或取消，由 `event.delivery_status` 区分 failed/cancelled。无结果或未知异常表示未确认，按未知结算。
- 补回事件使用非流式，仍可调用本轮语音和照片工具。普通文字在有效回复锁定后划分下一批，语音和照片直接发送时在首个实际发送动作前锁定批次。平台一旦受理，后续新消息另起一轮。

## LivingMemory

补回和轻忙短告知都会在模型钩子前设置 `event.get_extra("life_delivery_v1") is True`。召回照常。原自动用户记录和助手反思延后至送达后。

OneBot 和 QQ 官方须返回有效消息编号，个人微信须返回成功的业务回执。忙碌插件只把确认接受的内容传给 `record_delivered_exchange`。入参包含当前角色、原始聊天记录 ID、稳定事务编号、原用户文字与必要媒体占位。短告知的用户消息列表为空。

入队和开始生成前读取 `get_delivery_epoch(umo)`。代数匹配才将生成前的值作为 `expected_delivery_epoch` 传入送达提交。清空记忆后，旧轮次不会填回刚清空的长期记忆。原生聊天历史按实际送达独立结算。
