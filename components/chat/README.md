# 自然私聊

支持 AstrBot 4.26.0 起的版本。建议搭配角色生活日程 1.0.8 起的版本，使用睡眠和近期变化联动。角色忙碌或睡着时留住私聊，空闲后接着回。有新的生活话题或约好的联系到时间，也可以主动开口。一次设置一条私聊。

## 开启

1. 在目标私聊发送 `/sid`，复制返回的完整编号到「要接管的私聊」。
2. 确认这条私聊使用日程所对应的人设，打开「启用自然私聊」。设置保存后发一句普通私聊消息，插件会自动识别并记住机器人账号。
3. 「忙时暂存，空闲后回复」和「空闲时有话题再主动开口」可以分别开关。主动次数和照片上限只统计主动联系。

## 从旧版本迁移

用此版本覆盖原忙碌状态插件，保留插件编号和 `data/plugin_data/astrbot_plugin_life_busy`。原暂存队列继续使用。先核对旧忙碌和旧主动消息指向同一条私聊，再停用旧主动消息插件。两个目标不同须先确定唯一目标。将旧主动的每日主动次数、连续未回复上限、语音和照片设置及自定义提示词带入新的设置。

首次启用时会按目标私聊读取旧 `data/plugin_data/astrbot_plugin_life_proactive` 中对应的主动记录，另存到自然私聊数据目录下的 `proactive`。原记录继续保留。迁移后的主动次数、未回复计数和未结算轮次会继续处理。两份记录中的已绑定机器人账号或平台不同，后台会报错并停止接管该私聊。

## 支持的平台

| 平台 | 自然私聊可发 | 使用条件 |
| --- | --- | --- |
| NapCat 和使用 AstrBot OneBot v11 适配器的兼容机器人 | 文字、图片、语音 | 可以处理适配器收到的私聊撤回通知。 |
| QQ 官方机器人 WebSocket 与 Webhook 单聊 | 文字、图片、语音 | 补回使用 QQ 官方主动单聊，受机器人发送权限、用户接收设置及平台额度影响。 |
| 个人微信 iLink | 文字、图片 | 需要同账号的有效私聊凭据。语音台词改为文字发送。 |

只处理上述适配器的单独私聊。QQ 官方频道私信、群聊、公众号和网页聊天不进入忙碌队列。QQ 官方和 iLink 的现有 AstrBot 适配器未提供可用于清除积压的私聊撤回事件。

## 聊天中的表现

- 夜睡和午睡跟随角色的日程。普通私聊照常接话，暂存消息优先补回。已有的话题不会紧接在回复后再次主动发送。
- 只有到期约定或新的生活片段才提供主动开口的机会。已有的生成流程会结合聊天判断有没有具体内容值得分享。连续主动但未收到回复，达到设定上限后等待用户发消息。
- 用户明确说自己稍后回来找角色时，主动联系等待用户开口。用户说晚安或先睡时，当晚停止主动，按角色日程的夜睡结束时间恢复。答应明早联系的约定沿用日程里的约定记录。

- 日程标记看不了手机时，连续发消息也不会打断。偶尔看手机时，45 秒内收到至少三条，且都在当前安排内，才有一次 35% 的短告知机会。原消息仍等有空后完整回复。
- 有空后，旧消息和紧接着发来的新消息会先等一小段时间一起处理。回复锁定后到达的新消息排到下一轮。切换人设或新开聊天记录会分开保存积压。切回原记录并有匹配日程时，才继续补回。
- 空闲时连续发来的消息会短暂合并，沿用普通聊天的工具、思考显示和流式设置。等待中转为忙碌或睡眠时，消息留待有空后接着回。忙碌补回隐藏模型内部思考，保留要发的正文和媒体。
- 文字、可取得的图片、语音和引用会随积压保留。AstrBot 已识别的语音保留转写。旧版没有聊天记录标识的积压会继续留存，可用 `/busy_status` 查看，避免把它送到新聊天记录。
- 发送结果未知时，原消息继续保留供核对，自动重试只用于发送前出错或明确拒绝首条的情况。部分已送达时，历史只记平台确认接受的部分。可在绑定私聊使用 `/busy_status` 查看待回和未确认数。

积压和媒体缓存位于 AstrBot 的 `data/plugin_data/astrbot_plugin_life_busy`。重启会恢复待回消息，卸载前如需保留积压请备份此目录。

如启用 LivingMemory，请同时使用支持送达后记录和清空版本检查的联动版。自然照片需使用支持忙碌检查的联动版。主动消息、媒体和记忆的接入约定见 [联动接口](联动接口.md)。
