# 日程与自然语音联动审查（v1.0.3 candidate）

本轮从 v1.0.2 / `674e1b5` 继续，分支 `feat/voice-life-integration`。两个废弃分支不参与；main / v1.0.0 保留，未推送、合并或打发布标签。

## 联动范围

- 日程继续负责全局人设、生活状态及约定；自然语音继续负责音色、合成、语音发送和可选识别。没有把语音实现、密钥或新音色设置加入日程。
- 日程沿用聊天中的生活上下文，让模型参考活动、地点、心情和用户意愿选择文字或语音。只在本轮实际有 `tts_speak` 时建议使用，不虚构语音已经发送。
- 普通语音消息开放，实时通话和连麦仍受限。历史配置里的泛化语音禁令按通话理解，历史档案的旧能力限制在提示层失效；用户不方便或不愿听语音时继续用文字。
- 原配置、档案、日程、衣柜、约定和全局人设保存流程不迁移、不重建。沿用 v1.0.2 的原生保存及最新人设正文机制。
- 定时主动发语音未接入；聊天中记录了约定，不代表无人发消息时能自动执行。

## 交付信息约定

自然语音 v0.1.4 在当前事件的 `life_voice_delivery_v1` 列表追加 `{id, text, medium}`。`id` 为实际显示正文的 SHA256；`text` 为去除声音标签后的正文；`medium` 为 `voice` 或 `text`。只在发送成功返回后追加，合成成功本身不算成功交付。

日程在 `on_llm_tool_respond` 消费该列表，不使用工具参数或工具返回字符串冒充已发送台词。语音失败后文字成功可以进入原判断流程；两者都失败没有收据。事件结束后信息不持久保存，不传音频、密钥，不缓存另一个插件的实例。

每次处理检查主人、生活就绪、当前角色、聊天改日程开关、会话禁用和实例关闭状态；等待会话查询后重新核对角色。相同收据及相同正文在本事件只消费一次；不同正文和不同事件独立。记录处理标记后入队，入队异常明确记录日志，不因下一次工具回调再次判断同一句。

旧关键词设置仍支持未来语音约定；即时想听一句语音本身不增加判断调用。普通文字入口取实际 Plain 内容，不使用音频或空结果里的旧模型正文。提示长度由 800 调整为 1000 字符，避免新增语音说明挤掉已有失约提醒。

## 验证证据（2026-11-06）

- 主代理全套测试：918 项通过；Ruff、Git 差异格式、70 个 Python 文件的 Python 3.10 语法检查通过。
- 独立审查使用真实 AstrBot 4.26.0、4.29.0，每版按先语音/先日程两种顺序加载，每次 17 组联动检查全部通过；另复验 7 条普通语音与实时通话边界。
- 集成使用真实两插件处理函数、MainAgentHooks、runner/executor 与 LifeEngine.enqueue_chat 初筛。模型、音频、平台发送和会话策略查询为测试替身，禁止网络，运行资料在隔离目录。
- 覆盖成功语音、合成失败回退、发送失败回退、双失败、流式开关、重复/不同正文、主人、换卡、关闭、未就绪、全局禁用、会话禁用、插件白名单、普通实际文字及入队异常。
- 复审已修复：入队异常后的重复消费；“和你实时语音说晚安”被误放行；新增语音说明导致既有失约内容被裁掉。
- 复现脚本及结果保存在项目开发目录 `.work/voice-life-integration/`，不随插件运行或进入安装包。

以上自动化结果不替代真实模型约定判断、真实收费语音或 QQ 送达验证。真实本机验收单独记录在项目协作记录，不能用模拟发送声称 QQ 已实发。

## 已有框架边界

AstrBot 4.26/4.29 普通文字 RespondStage 捕获发送异常后仍可能触发 after_message_sent，普通文字旧入口不能据此证明平台最终送达。本轮自然语音及其文字回退采用直接发送成功后生成收据；不扩展修改框架的普通文字送达机制。模型在调用工具前已经输出的流式文字也无法追回。
