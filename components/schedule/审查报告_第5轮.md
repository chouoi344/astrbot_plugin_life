本轮按“完成修改 → 交叉对抗性审查 → 浏览器验收与全套测试”执行。代码位于指定的新插件目录；真实 AstrBot 的配置、日程、衣柜及运行数据未修改，未部署或重载实机插件。

## 一、修改内容与对应测试

### 1. 查看日程与视图都能看到今日穿搭

- `查看日程`、`日程原计划`、`昨天` 在天气下方增加“👗 今日穿搭”，显示外出、居家、睡衣，以及已有的运动服和补充说明。
- 来源按当前衣柜顺序标“衣柜·穿搭N”；AI 搭配标“AI 临时搭配”。统一去掉重复的“临时搭配：”前缀。
- 每套文字描述最多约 60 个可见字符，超出加省略号；组合 emoji、肤色、旗帜、键帽和组合音标保持完整。视图保留完整描述，长描述可展开。
- 时间轴每段增加外出服、居家服、睡衣或运动服标签，连续穿同一套也显示。
- 视图顶部新增“今日穿搭”卡片，显示来源、当前编号、缩略图和补充；手机下采用紧凑单列，小缩略图与正文并排。
- `schedule/today` 增加穿搭行、补充和逐段标签。缩略图由稳定 ID 读取，公开接口不返回本地路径。

对应：`test_round5_text.py` 的查看/原计划/昨天、运动、动态编号、旧数据、长文与 emoji 用例；`test_round5_frontend.py` 的卡片、标签、全文展开、缩略图、错误占位与安全文本；`test_round5_api.py::test_schedule_projects_complete_outfits_sources_labels_and_private_path_boundary`。

### 2. 手动把 AI 搭配收进衣柜

- 新增管理员写接口 `POST wardrobe/collect`，全插件现为 14 条固定路由、9 个写接口。每套可收藏的 AI 搭配有“收进衣柜”按钮，保存后显示已收藏及衣柜编号；原本来自衣柜的条目没有收藏入口。
- 使用与添加穿搭相同的描述、分类、季节校验和配置保存流程。新条目去临时前缀，按外出/居家/睡衣/运动分类，季节取该业务日所在季节。
- 同一套重复点击、并行点击、衣柜已有等价描述时，复用已有 ID 和元数据。已有描述可兼容分项标签、全半角、空白及标点的格式差异。
- 收藏成功绑定当天 `outfits` 或 `sport_outfits`，更新 `plan`、`actual` 和 `changes[].slots` 中对应的衣服引用。活动、时间、地点、心情、手机状态等事实保持原样。
- 收藏在共享配置锁和日程修改锁内提交，顺序固定为配置锁 → 日程锁；写失败尝试还原配置及日程。即使日程文件已写入后才抛错，也有回滚测试。
- 请求包含业务日期、穿搭位置和内容指纹；跨业务日、内容已换新或字段无效时给出中文刷新提示。前端按日期、位置和指纹隔离迟到结果。
- 空衣柜提示按指令完整替换，说明每天会临时搭配、可从今日日程收藏，也可自己添加；衣柜底部说明使用保存与选衣的用户语言。
- 本轮采用视图收藏入口，未增加可选的收藏指令。

对应：`test_round5_api.py` 的四分类、当前季节、重复/并行点击、已有描述、编辑删除、旧字符串、两套运动服、跨业务日、错误输入和持久化失败；`test_round5_frontend.py` 的收藏成功、重复、错误恢复与迟到回包；`test_round5_audit_collect.py` 的事务和锁等待探针。

### 3. 临时搭配保持风格并参考实际穿衣历史

- 提示词加入身份、爱好、人物设定，以及最近 `outfit_no_repeat_days` 天 `actual` 实际穿过的描述；包括 AI 临时搭配和运动服，未实际穿过的计划不作为穿衣历史。
- 新临时搭配采用六项结构：整体风格、服装、鞋袜、配饰、发型、妆容。空项不输出，展示和收藏时统一格式化为与衣柜相同的分项文字。
- 兼容旧日程中的字符串描述、带临时前缀的对象及缺少新字段的数据，读取时进行兼容投影，用户无需手工迁移。
- 对规范化后的精确重复描述，使用现有内容修复流程让模型重写。语义相似、身份风格和天气适配继续由提示词约束，不将文本比对描述为语义识别。
- 受限互动继续按第 3/3.1 轮规则逐句清理；正常家人朋友生活和其余服装分项保留。
- 收藏与模型等待并发时，提交从最新日程重新保全已收藏引用；普通重写、聊天修改、档案后补齐、业务窗口修复均已覆盖。

对应：`test_round5_outfits.py::test_generation_saves_six_part_temporary_outfits_and_locally_filters_forbidden_text`、`test_generation_prompt_uses_actual_temporary_history_and_character_style_and_repairs_exact_repeat`、`test_collection_during_model_wait_survives_every_day_commit`；独立 `test_round5_audit_generation.py` 的实际历史、格式重复、受限句局部清理，以及模型等待期间编辑/删除的 8 个实例。

### 4. 第二阶段接口准备

`get_current_state()["outfit"]` 的 `outdoor`、`home`、`sleepwear` 均返回对象，另有 `sports` 数组。每套至少包含：

| 字段 | 含义 |
| --- | --- |
| `description` | 去临时前缀后的完整描述 |
| `id` | 稳定衣柜 ID，临时搭配为空 |
| `temporary` | 是否 AI 临时搭配 |
| `category` | 外出、居家、睡衣或运动 |
| `image_path` | 已存在展示图的本地绝对路径，没有则为空 |

编辑衣柜条目后，当前投影采用该 ID 的最新描述与编号。删除后，本轮选择**保留当天快照描述并标“已从衣柜删除”**，图片路径为空，不自动重建已删除条目。

`get_life_context()["outfit"]` 继续返回当前穿着的描述字符串，运动服也采用同一个实际引用，兼容现有调用；聊天注入使用可读描述。公开视图使用缩略图数据，不暴露内部本地路径。README 已同步接口说明。本轮未实现生图。

对应：`test_round5_outfits.py::test_current_state_exposes_structured_refs_image_path_and_live_edits_with_legacy_string_context`、`test_current_sports_outfit_and_legacy_context_use_the_same_live_sports_reference`；`test_round5_api.py::test_existing_same_description_reuses_id_image_and_original_metadata` 使用真实临时缩略图文件检查内部路径与公开图片边界。

## 二、对抗性审查结论

交叉审查由未实现对应模块的负责人编写独立探针，发现的问题交原负责人修复，再复验。

| 重点场景 | 结论与验证 |
| --- | --- |
| 衣柜全空、缺少分类、季节或气温不适配 | 三套和已有运动服按实际选中结果标来源；缺分类会生成临时搭配。沿用原衣柜的季节放宽策略及气温过滤，来源不会仅按“衣柜是否为空”猜测。`test_round5_outfits.py`、原 `test_wardrobe.py` 与新 API/前端来源用例覆盖。 |
| 收藏后立即重写、聊天改动、档案补齐 | 收藏 ID 和非临时标记保持，提交不会被旧模型快照覆盖。独立测试还覆盖窗口修复，以及等待期间编辑/删除衣服，未发生引用丢失、重复新建或复活已删除衣服。`test_round5_api.py::test_collect_while_model_waits_survives_all_day_update_paths` 的三路径和 `test_round5_audit_generation.py` 的八实例。 |
| 收藏后编辑、删除、重排衣柜 | 编号按当前顺序，编辑采用最新描述；删除保留当天快照并标已删除，当前状态、文字、视图和注入均能读取。`test_round5_text.py`、`test_round5_outfits.py`、`test_round5_api.py` 和独立视图审查覆盖。 |
| 收藏与日程同时写入 | **发现并修复**：收藏提交后，等待中的 GET 会用旧日程和新衣柜拼出临时来源。现在在同一配置锁/日程锁内一次获取日程、状态、槽和衣柜快照，出锁只读取图片。独立 `test_schedule_get_waiting_behind_collection_reads_committed_day_and_source` 由红转绿。 |
| 收藏成功后迟到旧刷新 | **发现并修复**：合法旧 GET 在网络上晚到，会把已收藏显示退回临时。现在所有日程读取统一记录请求发出时的收藏版本，只修正该请求开始后确认、且同日期/位置/指纹的旧临时快照；收藏之后才发出的 GET 仍能正确显示编辑或删除。独立 `test_round5_audit_view.py` 的竞态和原负责人补的负例通过。 |
| 多套、重复及失败保存 | 两套空 ID 运动服并行收藏仍各绑各的槽；已有格式等价描述复用原 ID；保存失败、写入后抛错均还原两端；等待锁跨业务日会重新核对日期。`test_round5_audit_collect.py` 五项全部通过。 |
| 很长文字、emoji、特殊符号 | QQ 限长保持组合字符，换行不冲乱来源行；视图保留全文且使用安全文字节点，标签和描述中的特殊符号不会当 HTML 执行。本地路径不会作为浏览器图片地址。文字 14 项与独立视图 6 项通过。 |
| 旧数据 | 旧字符串和带临时前缀对象能展示、收藏；新增字段缺失时安全降级；收藏会绑定成稳定引用。只读投影不重写历史文件，收藏仅修改指定套装引用。相关兼容、缺失数据及旧运动描述测试通过。 |
| 用户文字 | 空衣柜说明按指定原文，来源、收藏成功/重复、过期、错误与已删除说明均为可读中文；`AI 临时搭配` 为指令指定来源标记，内部字段和异常类型不显示给用户。 |

## 五、用户实机确认步骤

1. **保留原资料更新**：按 README 的安全更新方式替换并重载插件，保留原配置和数据；更新现用插件时使用更新或代码覆盖流程。
2. **发送查看日程**：在 QQ 发送“查看日程”。天气下面应出现“👗 今日穿搭”，有外出、居家、睡衣及补充，来源正确；每段末尾都有衣服标签。再看“日程原计划”“昨天”，也应有穿搭说明。
3. **从日程收进衣柜**：打开插件视图 → 今日日程 → 找到一套“AI 临时搭配” → 点“收进衣柜”。按钮应显示“已收进衣柜·穿搭N”；进入衣柜，应出现这套完整描述，分类正确，季节默认当天季节。
4. **检查重复与刷新**：对同一套重复操作或刷新，衣柜中应仍只有一条对应衣服；回到今日日程，来源应显示衣柜编号。两套不同搭配可以分别收藏。
5. **检查重写引用**：收藏后发送“重写日程”，完成后查看该套来源，应保持衣柜引用；原来已经发生的活动和约定仍在。聊天改动及档案后补齐时也应保留该引用。
6. **检查编辑和删除**：在衣柜编辑这套描述，返回今日日程应采用当前描述。删除后，今天仍能显示原快照并标“已从衣柜删除”，查看日程和聊天不应报错。
7. **检查图片和长文字**：给衣柜中某套上传展示图，在它成为今日穿搭时查看缩略图；手机上展开较长描述，应看到全文，文字回复保持简短，emoji 不破碎。
8. **观察后续临时搭配**：衣柜缺少某类衣服时，后续生成应采用符合身份、爱好、季节天气的分项描述，并参考最近实际穿过的衣服。若实际模型给出语义相近搭配，可进一步反馈具体样例。

本轮未实现生图功能，只有用户手动收藏时才把对应 AI 搭配保存到衣柜。
