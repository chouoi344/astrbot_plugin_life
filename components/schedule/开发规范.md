# 插件开发与版本管理

- **仓库范围**：仅插件代码、测试、说明、审查报告和 `review_assets/` 截图。工作区指令、虚拟环境、缓存、日志、密钥及 AstrBot 运行数据不入库；提交前检查敏感信息。
- **每轮一个分支**：从 `main` 新建，例如 `stage2-photo`、`stage2-fix-1`；在对应分支开发，保留现有未提交修改。
- **小步提交**：每完成一个可检查的步骤提交一次，用中文说明具体改动，例如“生图：加男女姿势池”。
- **合并前验证**：全套测试、Python 3.10 语法检查、`ruff check` 全通过，再合并回 `main`。
- **版本与发布**：用户实机测试通过后才打新版本标签；第 2 阶段为 `v2.0.0`，同阶段小修如 `v2.0.1`、`v2.1.0`。同步更新 `metadata.yaml` 与 `CHANGELOG.md`，每次合并和打标签后推送 GitHub。初始第 1 阶段基线为已实机测试的 `v1.0.0`。
- **保留历史**：不强制推送，不改写已推送历史。修错使用 `git revert` 创建撤销提交；任何会丢弃修改的命令先征求用户确认。

## 查看历史和回退

打开 GitHub 仓库，在提交记录里能看到每一步改动；标签页可以下载对应版本，发布了 Release 后也可在 Releases 看版本说明与下载文件。

想回退时，告诉 Codex“退回到 v1.0.0”。Codex 会核对该标签，导出那个版本的插件文件供你部署；需要撤销后续代码时会新增撤销记录，保留历史。已有配置和日程数据保存在 AstrBot 的数据目录，代码回退会保留这些资料；部署时也应保留原数据目录。
