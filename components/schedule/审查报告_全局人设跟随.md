# 全局人设跟随审查（v1.0.2 candidate）

本轮候选已于 2026-11-06 完成本地检查与 AstrBot 4.29.0 实机验收。
开发沿用 `main / v1.0.0 / 71148dad` → `v1.0.1 候选 / 4437bfe` → `fix/global-persona-follow`，不包含废弃生图分支。
本轮尚未推送、打标签或公开发布。

## 本轮行为

- 日程只跟随 AstrBot 的全局默认人设，不读取单独聊天会话的人设，也不保留插件独立选角入口。
- 首次使用在 AstrBot 插件管理中打开本插件卡片设置，点击“保存并关闭”后，后台依次准备档案、日程和穿搭。
- 视图移除人设下拉、切换、开始生成和初始化继续重试；保留日程、档案、衣柜、基础设置四个板块及原有编辑功能。
- 视图显示实际全局人设名称、准备阶段和失败原因；准备期间每 5 秒检查状态，完成后自动读取生活资料。
- 其他状态每 60 秒检查全局角色；日程沿用原有刷新周期。未保存编辑不会被后台状态响应覆盖。
- 未就绪时禁止读取或注入旧生活资料，基础设置仍可用；失败后到原生插件卡片设置修改并保存，继续未完成步骤，复用已成功步骤。
- 同一人设 ID 修改正文，保留现有生活资料；提示“后续生成采用最新人设，已有资料保留”，不建议每次重生档案。
- 每次真正生成现读最新正文；最新人设事实优先，旧档案、作息摘要不能覆盖新设定。已经发生的生活事实继续保留。
- 全局默认 ID 变为另一张人设时，沿用备份 A：先备份旧档案、日程、衣柜、约定、事件，新角色从零准备；迟到的旧任务不能写入新角色。
- 城市、模型等设置继续保留；同角色保存这些设置不重复初始化。是否换角色按 AstrBot 实际人设 ID 判断。
- 默认人设为空、已删除或正文不可用时显示明确原因，不静默回退到其他人设。

## 保存与兼容审查

- 已研究 AstrBot 4.26.0 与 4.29.0 的实际原生保存、配置写入及插件重载流程，不把普通视图保存当作首次启动入口。
- 已核实带 BOM 的配置读取约定，以及 `GET setup/status` 的只读边界：查看状态本身不触发模型生成、备份或换角。
- 原生旧表单使用单份最新生活快照保护，已复验后台任务与旧表单交叉保存、写入失败恢复和普通设置保存不增长版本；保留新模型和城市设置。
- `settings/get` 与 `settings/save` 移除 `persona_id/personas`，视图不再调用 `setup/start`，也不依赖旧的 `can_start/requires_reset`。

## 验证结果

- 主代理最终全套测试：844 项通过；Ruff、差异格式、JavaScript 语法和 69 个 Python 文件的 Python 3.10 语法检查通过。
- 独立审查使用两版真实 AstrBotConfig 和临时资料验证保存事件识别、旧表单保护及失败恢复；这些检查使用模拟模型，没有实际接口费用。
- 内置浏览器检查电脑与 390px 手机模拟页和真实页面：基础设置、日程、档案、失败指引、取消选角和开始按钮，未见溢出或控制台错误。
- 开发预览使用独立模拟数据，不连接真实模型，不保存实际生活资料；预览脚本不进入安装包。

## 本机验收

- 覆盖安装后仍等待原生设置保存；原配置已有字段值及 5 个原运行资料文件保持不变，安装没有开始生成。
- 通过真实原生设置“保存并关闭”启动准备；旧默认助理资料先整套备份，再为用户当前全局角色生成档案和日程。备份校验通过，原配置资料与 5 个旧数据文件逐一比对一致。
- 档案采用的人设正文哈希与 AstrBot 当前全局卡片正文一致；用户填写的城市保留。真实模型完成一轮档案、21 段连续日程及外出、居家、睡衣三套临时穿搭，状态为 ready。
- 生成期间打开原生设置，生成完成后保存这个旧窗口；档案、当天日程和尝试记录哈希均不变。再普通重载该插件，结果仍不变，档案尝试次数保持 1。
- 已核对本机安装文件与候选包一致。实机截图与更新前资料备份保留在项目的“本机测试环境”目录，不放入公开源码包。
- 真实 QQ 聊天改日程未测试；切换到另一张新卡、同 ID 正文修改后的后续生成、故意制造失败后的续做，以模拟模型测试为证，没有改动用户人设正文来额外调用模型。
- 本记录不保存密钥、完整人设或具体账号，角色与模型名称均由实际配置提供。
