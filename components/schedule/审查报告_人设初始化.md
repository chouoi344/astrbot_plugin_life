# 人设初始化修复审查（v1.0.1 候选）

基于 `main` / `v1.0.0` 的 `71148dad5b7a8f1e4321da9e726e61e75b3acb1e` 开发，分支 `fix/persona-initialization`。不包含已废弃的生图分支内容；尚未推送、打标签或公开发布。

## 行为

- 首次安装等待明确选择人设并点击开始。空选择、失效人设、空正文显示原因；默认助理也需要明确选择。
- 顺序准备档案、日程和穿搭，整套成功才用于聊天。失败显示阶段并等待手动继续；重启后的中断可恢复，已完成步骤不重复生成。
- 换角色先确认，再生成校验通过的整套备份，保留原文件。新角色不继承旧档案、衣柜、历史日程、约定和事件。仅保存选择不清除原资料。
- 同角色修改正文只提醒；手动重新生成时保留衣柜、约定、事件和过去事实。已有匹配角色的历史成功生活在升级时继续正常运行，跨日自动补日程。
- 页面只显示实际人设名称；没有固定个人名称、QQ 号、模型或电脑路径。

## 对抗性审查

检查了聊天注入、回复后判断、指令、外部状态接口、定时任务、天气、穿搭图片与视图任务查询。入口统一检查是否就绪，异步结果绑定本轮角色标识，换角色后不能继续写入或返回旧结果。

发现并修复：已完成日程在末尾失败后可能重复生成；配置保存失败只还原内存；旧后台任务可能返回结果或重新写回已归档记录。备份校验失败、移动失败及配置保存失败均有对应回归检查。

独立复核未发现阻断项；另用模拟模型验证了跨日补日程、重启续做、换选丢弃迟到结果和同角色重生成保留原资料四条流程。

## 验证结果

- 全套测试：**823 项通过**。原来要求自动首次生成的测试已改为明确开始，同时保留原有日程、天气、衣柜、权限与队列的检查。
- `ruff check .`、`git diff --check` 通过；68 个 Python 文件通过 Python 3.10 语法解析。
- 核对 AstrBot 4.26.0 与本机 4.29.0 的人设查找合同，使用实际人设列表及明确的 ID，不依赖默认回退。
- 内置浏览器检查电脑与 390px 手机页面：选择、保存、开始、分阶段显示、失败重试、换角确认提示、未保存输入保护；未见控制台错误。页面使用开发模拟数据，没有调用真实模型。
- 截图：`review_assets/persona-setup-desktop.jpg`、`review_assets/persona-setup-mobile.jpg`。开发预览脚本不在插件安装包内。

## 实机验收边界

真实模型生成、真实 QQ 聊天修改日程仍需用户确认后的实机验收；模拟测试通过不代表模型服务或 QQ 链路已验证。更新使用覆盖安装并保留配置与数据；已有角色不匹配时等待用户在页面确认，不自动付费重建。

换角色的整套备份位于插件数据目录 `role_backups/<时间>/life.zip`，原文件另外保存在同目录 `retired/`。同角色档案备份仍在 `profile_backups/`。
