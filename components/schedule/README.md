# 拟人化生活日程 Plus

插件 ID：`astrbot_plugin_life_scheduler_plus`，版本 `v1.0.5`。

角色拥有稳定生活档案、从生成时间连续覆盖至次日的时间轴、真实天气、长期事件、聊天约定和衣柜。全局共用一份状态，计划保留，聊天和小意外只改变实际记录的未来部分。

本插件管理生活状态和约定。自然语音、自然照片、生活主动消息和忙碌状态分别作为独立插件读取这份日程，保持地点、穿搭、心情和看手机状态一致。

## 平台与版本

日程核心与整套生活联动的最低要求统一为 AstrBot 4.26.0。本轮兼容检查范围是 4.26.0 至当前稳定版 4.29.4。后台显示的版本范围是运行要求；插件自身版本在名称旁显示。

平台标识覆盖 OneBot v11（包括 NapCat 和符合该协议的自制机器人）、QQ 官方私聊的 WebSocket / Webhook 接入、个人微信 `weixin_oc` 与本地 WebChat。日程按 AstrBot 消息接口工作，不要求用户 ID 是数字。主人 ID 必须填写对应平台提供的原始标识，QQ 官方 OpenID 和微信用户标识不能改成个人 QQ 号。不同渠道的发送能力由语音、照片、主动和忙碌插件各自处理；微信当前仅支持发文字和图片。

本机已检查 AstrBot 4.29.0 的实际接口与隔离回放。QQ 官方和微信尚未配置真实账号，不能将协议回放当作真实收件验证。未知的自定义协议需要单独适配，OneBot v11 自制机器人使用同一 OneBot 接口。

## 配合自然语音

同时启用自然语音 v0.1.4 或以上，并配置好音色及 `tts_speak` 后，角色可参考当前活动、地点、心情和用户意愿选择文字或语音；使用原有生活上下文，不重复配置角色。用户不方便听时仍用文字，没有可用语音工具时正常文字聊天。

语音里真正说出的台词会进入日程原有的主人检查、关键词初筛和约定判断；合成或发送失败但成功改发文字时也一样。所有发送都失败的内容不会被登记，声音标签不会当作正文，同一条交付不会重复判断。

普通语音消息已经开放，实时语音通话、连麦等限制保留。升级不删除旧档案、日程或约定，也不因开放语音重建生活。启用独立的生活主动消息插件后，它会按日程、免打扰和发送条件判断是否主动开口；仅安装日程插件不会定时发送消息。

## 安装与首次使用

1. 使用 AstrBot 4.26.0 或更新版本，Python 3.10 或更新版本。
2. 把本文件夹完整放入 AstrBot 的 `data/plugins/astrbot_plugin_life_scheduler_plus/`，安装本文件夹 `requirements.txt` 的兼容范围依赖，然后在插件面板加载。
3. 在 AstrBot 配好聊天模型。插件面板的 `llm_provider` 留空时，跟随默认参考会话对应的当前模型；也可明确选一个模型。
4. 在 AstrBot 中设置全局默认人设。插件自动跟随它，不再单独选择人设，也不跟随某个聊天会话的临时人设。默认人设为空、被删除或正文为空时会提示原因，不会静默使用其他人设。`owner_ids` 留空时主人就是 AstrBot 管理员，也可以填普通用户的 ID 作为主人。
5. 打开 AstrBot 插件卡片的设置，填写模型等信息并点击「保存并关闭」。首次保存后，插件后台先生成生活档案，再生成日程和穿搭，整套准备成功后才用于聊天。插件视图只显示当前跟随的人设、进度和错误，没有选角、开始或换角确认按钮。刚安装、普通重启和打开视图都不会代替首次保存。

首次准备失败或因重启中断时，页面显示阶段和原因。修正模型等设置，再从 AstrBot 插件卡片点击「保存并关闭」继续；已经成功的档案会保留，继续完成余下步骤。准备成功后，同一人设重复保存、修改模型或城市、普通重启都不重建档案和已有日程。天气暂时获取失败沿用原有降级方式。

首次保存启用后，将 AstrBot 全局默认人设换成另一张卡时，插件检测到变化就停止使用旧角色资料，校验整套备份后自动建立新角色的生活。后台每分钟检查，聊天时也检查角色是否仍匹配。备份包含档案、全部日程、衣柜和图片、约定、事件，保存在插件数据目录的 `role_backups/`，备份失败则保留原资料并停止。新角色不继承旧资料。本插件同一时间管理一个角色。

从旧版更新时，只采用与全局默认人设匹配的生活资料；不一致的旧资料在首次原生保存后先备份再重建。旧插件单独保存的 `persona_id` 不再作为角色来源。

同一张人设卡更新正文时，已有档案、当天安排、衣柜和约定保留。后续生成或主动重写时读取最新正文，最新人设事实优先，旧档案仅补充日常；旧身份和作息不会继续作为与新设定冲突的硬要求。读取正文不调用模型，修改文字不会触发额外的整套初始化。

角色时间跟随 AstrBot 全局 `timezone`，读取失败使用 `Asia/Shanghai`。每天默认 `07:00` 开始一个业务日，凌晨的记录属于前一天。

配置和数据与原插件独立，没有旧数据迁移。两插件的中文指令有重名，使用本插件前可在面板停用原插件，避免重复响应。

## 更新插件，保留档案和衣柜

**更新插件时不要先卸载，否则容易把档案和衣柜一起删掉。** 卸载窗口里的「同时删除插件配置文件」和「同时删除插件持久化数据」会清除相应内容；更新、重载与卸载是不同操作。下面的更新方式保留配置和生活数据。

只有本地 ZIP 包时，可以按这套通用步骤更新：

1. 完全退出 AstrBot，让正在生成的任务停止。先找到 AstrBot 使用的 `data` 文件夹；Windows 桌面版通常位于 `%USERPROFILE%\.astrbot\data`，以实际安装位置为准。
2. 将 `data/config/astrbot_plugin_life_scheduler_plus_config.json` 和整个 `data/plugin_data/astrbot_plugin_life_scheduler_plus/` 复制到另一个备份文件夹。前者保存生活档案和衣柜描述，后者保存日程、约定、备份和展示图。
3. 将旧的 `data/plugins/astrbot_plugin_life_scheduler_plus/` **代码文件夹**移到备份位置，备份放在 `data/plugins` 外面。解压新 ZIP，找到含 `main.py`、`metadata.yaml`、`core/`、`pages/` 的插件文件夹，将它放回 `data/plugins/astrbot_plugin_life_scheduler_plus/`。保持这个文件夹名称，避免多套一层目录；保留第 2 步中的原配置和原数据。
4. 重新启动 AstrBot，打开插件视图，确认原来的生活档案和衣柜仍在。依赖有变化时按安装步骤补装 `requirements.txt`；缺少依赖时先处理提示，再重新启动。

AstrBot **4.29.4** 还支持直接上传同一个插件的新 ZIP：在插件页打开安装窗口，选择「从文件安装」，上传新版包并等待加载完成。同名判断使用包内 `metadata.yaml`，原配置和数据会保留。已核对 **4.26.0** 的同一入口遇到已存在目录会拒绝覆盖；其他小版本如提示「目录已存在」，使用上面的通用步骤即可，保留已安装的插件和资料，不要为绕过提示先卸载。

通过已发布仓库安装、且仓库已有新版时，可使用插件卡片里的「更新」。更新会取得新版代码、处理依赖并重新加载；「重载」只重新运行当前安装的代码。核对依据见 [COMPATIBILITY.md](COMPATIBILITY.md#插件更新本地-zip重载与卸载)。

## 配置

- 档案：身份、居住、工作日与休息日作息、课表或固定安排、周期事项、假期、社交圈、爱好、手机习惯，在插件视图的「生活档案」中编辑。
- 天气：仅填写 `weather.city`；城市及名称变体都查不到时，根据档案居住地和人设地域参考广州或北京的真实天气（南北不明或同时出现时用北京）。配置与聊天保留原城市名，日程文字和视图注明参考城市；重新生成档案提取到真实城市后自动切回。断网时优先保留同地点缓存，无缓存则显示暂时获取失败并等待更新。空城市或关闭真实天气沿用季节模拟，旧 AI 天气仍标注模拟。
- 主人：只有 `owner_ids` 中的人能改变日程、添加约定、修改衣柜；留空时使用 `event.is_admin()`。其他人只读当前状态。
- 线上能力：目前角色与用户只能发文字和图片，限制连麦、语音通话、语音消息、视频通话、一起打游戏、线下见面。限制只针对角色与用户，和家人朋友的正常生活照常保留。语音消息和实时通话已分组，后续语音模块可以单独开放消息。
- 模型：高级配置 `judge_provider` 用于后台判断聊天，留空跟随 `llm_provider`；`image_provider` 用于穿搭图片转写。这两项默认隐藏。
- 参考：`reference_history_days` 默认 3 天；`reference_recent_count` 默认 10 条；`default_reference_umo` 指定参考聊天来源，聊天判断使用实际发生对话的来源。
- 衣柜：每套有稳定 ID、描述、分类和季节，在插件视图的「衣柜」中增删和编辑。新增或编辑时可上传 PNG/JPG/WebP 图片，受理后进入后台队列，自动提取服装、鞋袜、配饰、发型、妆容、颜色材质与版型，并填写分类和季节；确认后再保存方案。人物外貌、脸部特征、身材、肤色、场景、动作和镜头构图会排除。首图同时成为展示图。自动选择考虑季节、温度和最近重复，缺少类别时生成临时搭配。
- `surprise_probability=0` 关闭小意外，`auto_event_probability` 默认 `0`，关闭 AI 新事件（该项隐藏），`chat_change_enabled=false` 关闭聊天改日程和新约定。
- `extra_generation_prompt` 添加补充要求，时间轴 JSON 格式由代码维护。

同一人设正文发生变化时会显示保留现有生活、后续采用新设定的提示。仍可主动重新生成档案：先备份旧档案，再重写之后的日程，保留过去记录、衣柜、约定和事件，整套准备成功后恢复使用。

## 指令

中文指令和英文入口使用同一套实现。英文通过单个 `life` 入口分发，避免 `life profile` 误触发 `life profile regen`。

| 中文 | 英文 | 权限 |
| --- | --- | --- |
| 查看日程 | `life show` | 所有人 |
| 日程原计划 | `life plan` | 主人 |
| 重写日程 [文字/穿搭N/图片] | `life renew ...` | 主人 |
| 昨天 | `life yesterday` | 所有人 |
| 查看档案 | `life profile` | 主人 |
| 重新生成档案 | `life profile regen` | 主人 |
| 档案已确认 | `life profile ok` | 主人 |
| 查看约定 | `life promise` | 主人 |
| 取消约定 编号 | `life promise cancel N` | 主人 |
| 查看衣柜 | `life wardrobe show` | 所有人 |
| 展示 穿搭N [附图或引用图] | `life wardrobe image 穿搭N` | 主人 |
| 日程时间 HH:MM | `life time 07:00` | 主人 |
| 参考会话 [set/show/clear] | `life umo set` 等 | 主人 |

指令是否需要 `/` 等唤醒前缀跟随 AstrBot 设置。查看日程中的 `▶` 表示现在，`✓` 表示过去。

`查看日程`、`日程原计划`、`昨天` 都在天气下显示「今日穿搭」：外出、居家、睡衣，有运动服时另列运动，附穿搭补充。每套描述最多显示约 60 字，完整说明在视图中查看。衣柜来源显示当前顺序的「衣柜·穿搭N」，临时方案显示「AI 临时搭配」；衣服已删除时保留当天描述并标「已从衣柜删除」。时间轴每段末尾都标明外出服、居家服、睡衣或运动服。

衣柜工具 `life_wardrobe_list/remove/edit` 仅主人能用。新增方案与图片提取在插件视图的衣柜页完成；手动事件指令已移除。只读 `life_get_schedule` 返回今天完整实际时间轴。日程改动统一由发送回复后的后台判断处理，已删除原 `life_schedule_edit` 工具。

## 后台行为和数据

正常聊天注入只读状态，使用天气缓存。角色回复实际发送后才排队判断；连续消息等待 5 秒合并，同一时间只执行一个判断。失约解释须经后台确认确实在已发送回复中提起，才停止重复注入。

插件内所有模型调用共用一个队列，同一时间只发送一个请求。档案为空时优先生成档案，聊天判断公平排队；排队等待不计入下表的模型执行时间。队列和用途超时相互独立，避免多个大请求同时挤占模型。

| 用途 | 模型执行上限 |
| --- | --- |
| 生活档案 | 180 秒 |
| 日程生成或重写 | 180 秒 |
| 聊天改日程判断 | 60 秒 |
| 小意外、独立长期事件用途 | 120 秒 |
| 衣柜识图 | 195 秒 |

当前长期事件随日程同一份模型回复输出，共享这次日程的 180 秒预算；独立 `event` 用途保留 120 秒策略。

生活准备完成后的正常运行中，超时、连接错误等临时失败按 2 分钟、10 分钟、30 分钟逐步拉长自动重试间隔；内容为空、内容格式错误等情况保留原间隔（日程 10 分钟、档案 30 分钟）。普通日程为初次加最多 3 次自动重试，档案每个自然日最多 3 次自动尝试；窗口修复和档案后补齐各自沿用最多 4 次自动修复预算；被插件重载、卸载取消的尝试不占自动次数。状态和下次重试时间保存，重启后继续；`重写日程` 和「重新生成档案」可手动重试。首次准备与换角色准备失败时，修正设置后从 AstrBot 插件卡片点击「保存并关闭」继续，普通重启不会自动重试。

天气单个网络请求最长 10 秒，图片收集和 HTML 卡片有独立超时。衣柜识图先返回后台任务编号，再查询任务进度，排队期间持续显示等待状态；用户关闭编辑框、换图或离开页面后停止观察旧任务，迟到的结果不会覆盖新内容。

小意外时间持久化，重启恢复未来任务，过期任务跳过。调度器在重载时读取最新生成时间。卸载时停止调度器并取消后台任务。

数据位于 `StarTools.get_data_dir("astrbot_plugin_life_scheduler_plus")`：

```text
days/YYYY-MM-DD.json     计划、实际、变更、天气、当天穿搭和意外任务
setup_state.json        当前人设绑定、准备阶段和失败原因
runtime_config.json     最新生活资料快照，防止旧设置表单覆盖后台更新
role_backups/           换角色前的整套校验备份及保留的旧文件
events.json             AI 长期事件（默认不自动新增）
promises.json           约定和失约提醒状态
weather_cache.json      同地点坐标、真实/模拟天气缓存
profile_generation.json 档案自动尝试次数和重试时间
wardrobe_uploads.json    面板图片提取状态
view_tasks.json          视图后台档案和图片识别任务状态
view_uploads/            视图图片转写临时文件（处理完即清理）
files/                  AstrBot 配置面板保存的上传原图
profile_backups/         手动重新生成前的档案备份
wardrobe_images/         衣柜展示图
```

JSON 文件原子写入；损坏文件保留为 `.broken`。日程默认保存 30 天，结束超过 30 天的约定会清理。

## 内部状态接口

```python
state = plugin.get_current_state()  # 同步，独立副本，无网络或模型调用
context = await plugin.get_life_context(allow_generate=False)  # 缓存只读
context = await plugin.get_life_context(allow_generate=True)   # 必要时等待后台生成
```

`get_current_state()` 返回 `now/current_slot/next_slot/outfit/weather/events/promises_due/day_summary/profile_summary`。时间是带时区的 ISO 字符串；时段包含 `start/end/activity/location/phone/mood/outfit_type`，另附实际穿搭描述 `outfit`（字符串）与衣柜 ID `outfit_id`。运动装保留原有三种 `outfit_type`，通过时段自身的穿搭引用识别。

全局人设失效或整套生活尚未准备完成时，这些接口不返回旧角色或半成品生活；`allow_generate=True` 也不能绕过首次原生设置保存。首次准备从 AstrBot 插件卡片的设置保存开始。

`state["outfit"]` 的 `outdoor/home/sleepwear` 分别是外出、居家、睡衣对象，`sports` 是运动穿搭对象数组。每套包含以下字段，供后续生图模块直接读取；本轮提供数据接口。

| 字段 | 含义 |
| --- | --- |
| `description` | 完整穿搭描述，去掉「临时搭配：」前缀 |
| `id` | 衣柜条目 ID；尚未收藏的临时搭配为空字符串 |
| `temporary` | 是否为 AI 临时搭配 |
| `category` | 外出、居家、睡衣或运动 |
| `image_path` | 已存在的衣柜展示图的本地绝对路径；没有展示图时为空字符串 |

`get_life_context()` 兼容接口保留 `outfit/schedule/meta.style/timeline`，其中 `outfit` 仍为当前穿搭描述字符串，并返回当前时段、下一时段、天气、事件和当前时间。调用方读取套装 ID 或展示图时使用 `get_current_state()`。

## 四板块插件视图

在 AstrBot 插件卡片的视图入口打开「life」。默认衣柜，左侧固定导航可切换今日日程、生活档案和基础设置，底部显示连接状态。新入口为 `pages/life/index.html`，逻辑、样式和桥封装分别在 `app.js`、`style.css`、`api.js`；旧衣柜页面已移除。metadata.yaml 已按 AstrBot 规范声明 pages 列表，name 为 life、entry_file 为 index.html。原面板中的档案和衣柜已隐藏，视图仍正常读写同一份配置。

- **衣柜**：按季节筛选，筛选后保留原穿搭编号。可以添加、编辑、确认删除；上传或拖入 JPG/PNG/WebP 图片后自动提取衣着、分类和季节，支持人工修改后保存。每张图片最多 20 MB。桌面三列、平板两列、手机紧凑单列，长描述可展开。
- **今日日程**：展示当前业务日的实际时间轴、日期、星期、天气和今日概况。时间轴上方的「今日穿搭」卡片列出外出、居家、睡衣及运动搭配，有展示图时显示缩略图，长描述可展开；临时搭配可点「收进衣柜」，保存后显示衣柜编号。同一套重复点击或衣柜中已有相同描述时复用已有条目。收藏后保留当天的穿搭引用，已经发生的活动保持原样；删除衣柜条目后仍显示当天快照并标明已删除。每段时间轴都有衣服标签，过去的时段变灰，当前时段高亮。生成中前 3 分钟每 5 秒自动检查，较慢时提示等待较久，并改为每分钟确认一次，完成后仍会自动显示；失败时显示原因和立即重试，手动重试不受自动次数限制。就绪后每分钟同步当前时段和业务日；离开板块停止查询。显示时间使用插件时区。
- **生活档案**：编辑十个档案字段，显示生成时间和人设匹配状态；保存手动修改时确认当前人设哈希。重新生成先备份旧档案，在后台执行。自动或手动生成期间统一显示正在生成，隐藏旧的失败和重试时间；结束后再显示最新结果。手动重试不限次数，生成中重复请求会等待同一个任务。页面查询进度，快速观察达到 4 分钟后改为每分钟确认一次，完成后仍会自动显示；离开页面后任务继续，卸载时取消。
- **基础设置**：编辑城市、每日生成时间、主人 ID、可用模型、作息浮动、小意外概率和聊天关键词；空模型表示跟随 AstrBot 当前模型。关键词留空会判断每一轮主人聊天。保存后立即生效；修改生成时间会重新排期，修改城市会清除旧位置缓存，不重建已有档案和日程。主人 ID 可用空格、中英文逗号或换行分隔；空城市使用模拟天气。首次启用与失败续做仍从 AstrBot 插件卡片设置的「保存并关闭」触发。保存期间防止重复操作，未保存就切页会提醒。

视图通过 AstrBot 官方桥访问插件 API，页面不直接读取登录凭据。写接口仅允许当前 Dashboard 管理员登录凭据；聊天主人身份、插件 API key、页面资源 token 均不授予写权限。只返回本插件的必要数据，不包含模型密钥。

旧配置面板上传的图片数据仍能在启动时后台扫描和提取；日常上传入口为衣柜视图。两者共用相同的穿戴信息整理和展示图存储；模型失败或配置提交失败保留旧描述与展示图。

四个板块的本地预览截图在 `review_assets/life-wardrobe.jpg`、`life-schedule.jpg`、`life-profile.jpg`、`life-settings.jpg`。预览使用独立示例数据和模拟桥，真实 AstrBot 中的面板认证、模型、保存重载等完整流程仍需实机验收。
